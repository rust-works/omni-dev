# ADR-0091: Gated Sheets and Docs Content Writes over MCP

## Status

✅ Accepted (2026-10-03, #1641).

Extends [ADR-0073](adr-0073.md) §12, [ADR-0075](adr-0075.md) §9,
[ADR-0076](adr-0076.md) §12 and [ADR-0080](adr-0080.md) to MCP writes.
Implemented by `src/mcp/drive_write_tools.rs`; operator policy is unchanged.
The read tools remain in their separate read-only modules.

## Context

Sheets and Docs have read-only MCP tools, but content writes remain CLI-only.
Issue #1641 asks whether writes should be exposed, how previews work, and how
agents distinguish stale revisions and interpret replacement estimates.
[ADR-0080](adr-0080.md) now places device-owner consent, a pinned backup and a
file-version check inside the lease/write engines. A tool can pass a lease
without moving these checks into its handler. Engine logging likewise applies
to MCP calls, whose request context supplies `source: mcp`.

Three options are viable: retain CLI-only writes; expose writes but require a
shell to acquire leases; or expose a narrow content-write tranche together
with lease acquisition. The first avoids adding a mutation surface but leaves
MCP-only clients read-only. The second preserves shell-only acquisition but
also excludes those clients whenever policy requires a lease. We choose the
third: the existing OS consent prompt remains the authorisation step, and the
same engines govern both transports. A preview is useful preparation; it does
not prove human approval. Operator lease exemptions already exist and must
remain explicit in descriptions rather than being hidden behind a claim that
every MCP write requires Touch ID.

## Decision

We will expose the following narrow tranche, with thin handlers delegating to
existing engines:

1. **Tools and fence.** Add `drive_docs_replace`, `drive_docs_append`,
   `drive_sheets_write`, `drive_sheets_append`, `drive_sheets_clear` and
   `drive_lease_acquire`. Content writes use the `DocsWrite`/`SheetsWrite` gate,
   existing account credentials, lease checks, ledger locking and audit paths.
   `FilesApi` mutation wrappers, including `rename`/`move_to`, remain
   `pub(in crate::drive)`, as do Docs/Sheets mutation wrappers: an MCP module
   cannot call these wrappers directly. This is a fence around the wrappers,
   not a claim that arbitrary HTTP is impossible. Add an architectural guard
   against direct wrapper calls from MCP alongside the visibility restriction.
   Gate classification may read Drive metadata; a blocked write makes no
   mutation or Docs/Sheets content-fetch call. Engine-owned attempt logging
   still records refusals, and leased writes retain fail-closed write-ahead
   auditing. Tests must pin these properties for MCP request contexts.
2. **Preview and parameters.** `dry_run` defaults to `false`, matching the CLI
   and existing MCP mutation tools (STYLE-0029). Descriptions tell clients to
   preview first: previews need no backup lease and perform no mutation.
   Preview and real runs use the same engine classification and request
   construction. A preview neither reserves a version nor authorises a later
   write; the real call reruns the checks. `lease` accepts an engine token,
   and is optional for previews or an operator rule with `require_lease: false`.
   MCP never accepts folder rules, ledger paths, authentication policy or a
   headless-waiver flag. Optional `account` has the same meaning as on reads.
   Replace uses literal search and optional `ignore_case` (default `false`).
   Append accepts mutually exclusive `text`/`text_path`; Sheets write/append
   accept mutually exclusive inline rows/`values_path`, reuse CLI file parsing
   (`auto|csv|tsv|json`), and default `input` to `user-entered` (`raw` is the
   alternative). Reject ambiguous inputs before any engine call.
3. **Acquisition and operator policy.** `drive_lease_acquire` accepts `file_id`,
   optional integer `expiry_minutes` (1–1440, the CLI/engine bounds), and
   `account`. Share CLI policy resolution through `drive::lease::settings`:
   explicit expiry, then operator env/settings, then the existing default;
   backup-directory and authentication policy likewise retain their layering.
   Use the selected account's `lease_backup_folder_id` for native backups.
   The same engine authenticates, backs up, pins the version and records the
   lease. Device-owner authentication allows Touch ID or account password;
   operator `biometrics_only` requires Touch ID. `NoAuthenticator` refuses
   unless operator env/settings explicitly allows headless acquisition;
   `PolicyUnsatisfiable` is never waived. MCP cannot select that waiver; an
   acquired result reports `headless_waiver` unchanged. A denied prompt takes no backup and mints no
   token. Existing live leases are reused (`already-leased`), following the
   engine, rather than prompting and minting a second lease. One authorised
   lease covers repeated writes to that file until its fixed expiry, with
   version checks and ledger refresh after each successful write; it does not
   grant permission for other files or extend itself.
4. **Machine-readable outcomes.** Return the engine's complete tagged outcome
   as YAML without renaming statuses or dropping fields. Use exhaustive enum
   matching to set MCP `is_error`: successful previews (`would-*`), applied
   writes and acquisition (`acquired`/`already-leased`) are successful;
   blocked, refused, denied, unavailable, failed and partial outcomes are
   errors. Do not infer success from a string prefix. Preserve structured
   refusal data even when `is_error` is true. Unexpected handler errors use
   the shared `tool_error` helper. This deliberately differs from the Sheets
   CLI outcome exit convention in ADR-0073 §13/ADR-0075 §10: MCP clients need
   an error signal as well as a body they can parse.
5. **Staleness and estimates.** Keep `stale-revision` distinct from
   `refused-lease-stale`. The former means Docs rejected the per-call
   `requiredRevisionId`; reread and retry only through the complete engine,
   which may now refuse the backup lease as stale. The latter needs a fresh
   authorised backup lease; it is not permission to retry with the same token
   or bypass freshness. Acquisition returns an existing live lease even when
   its version is stale. Release that token with `omni-dev drive lease release`
   before reacquiring, or wait for expiry; MCP-only clients must wait or ask
   the operator to release it. Acquisition does not expose `supersedes`.
   `WouldReplace.occurrences` stays an estimate over the
   body only, excluding headers, footers and footnotes. Zero does not suppress
   a real replacement request; the real `occurrences_changed` is authoritative
   (ADR-0076 §7). Put these qualifications in the tool descriptions.
6. **Timeouts and future scope.** The OS prompt may wait up to 120 seconds.
   A cancelled/timed-out MCP call can leave an acquired lease or an applied
   write whose result was not delivered. Clients must inspect the file/lease
   state before retrying, especially append; cancellation is not rollback.
   Recover an undelivered token by explicitly repeating acquisition for the
   same file/account: a live lease returns `already-leased` with its token
   without another prompt or backup. Once the earlier call has finished, a
   retry with no live lease performs normal acquisition and consent. Do not
   automatically retry while the first call may still be running: racing
   acquisitions can spend redundant prompts/backups. Before shipping, test
   this recovery flow and verify interactive prompt/runtime behaviour. There
   is no `drive lease list` today. Docs/Sheets create, typed structure/format/
   delete/protection verbs are later additions under this contract, with
   verb-specific schemas and tests; create retains ADR-0080 §9's backup-lease
   exemption and its `Create` gate. Plain Drive writes and lease restore,
   release and prune stay CLI-only. No raw batch-update tool is planned.

## Consequences

- **Positive.** MCP-only clients can edit content with the same gate, consent,
  pinned backup, freshness and audit machinery as shell clients. Preview and
  refusal results remain machine-readable, and explicit `is_error` prevents a
  blocked write from looking successful.
- **Negative.** The agent gains a reusable file-write window after consent,
  rather than approval per edit. Operator exemptions can remove the lease or
  human-presence requirement just as on the CLI. Acquisition needs a usable
  authentication session by default. Strict client timeouts introduce uncertain
  outcomes; token recovery and interactive runtime behaviour need verification.
  MCP-only clients cannot release a stale live lease and must wait for expiry
  or ask the operator to release it from a shell.
- **Neutral.** Read tools remain read-only. OAuth grants, folder rules, backup
  fidelity, lease lifetimes and write engine invariants are unchanged. The MCP
  implementation supplies typed schemas, routing, engine regression coverage,
  user documentation and existing-token recovery. Interactive OS prompt and
  client-timeout behaviour still require a live integration check before release.
  Narrowing the library wrapper visibility removes direct external
  `FilesApi::rename`/`move_to` access; callers must use the public Drive engines.
