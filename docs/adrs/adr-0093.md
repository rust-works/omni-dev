# ADR-0093: Google Slides object reads and guarded text replacement

## Status

✅ Accepted (2026-10-02)

## Context

Issue [#1630](https://github.com/rust-works/omni-dev/issues/1630) separates
Slides from the Docs integration. Drive export cannot expose slide/page/element
object IDs, table cell coordinates or a Slides revision token. Slides is an
object graph, unlike Docs' UTF-16 index model. The shared Google transport and
Drive permission/lease engines already provide the infrastructure needed.

Existing `edit`, `docs-write` and `sheets-write` grants were issued when Slides
was unreachable. Reusing them would widen consent without a configuration change
([ADR-0073](adr-0073.md), [ADR-0076](adr-0076.md)). Slides batchUpdate supports
`requiredRevisionId`, while the separate Drive write lease protects the native
backup and audit trail ([ADR-0080](adr-0080.md)). Both must apply.

## Decision

We will expose `drive slides info`, `read` and `replace` in a separate Slides
module under Drive, sharing OAuth sessions and the mutation visibility fence.

1. **Complete reads.** Fetch presentations without a fields mask, preserving
   recursively grouped elements and notes. Enforce a 64 MiB bound on declared
   and actual decoded response bytes, including chunked transfer. Model unknown
   element kinds tolerantly. Read rows identify slide, page and element IDs and
   table cell grid coordinates; notes have a separate kind/page identity.
   `info` reports the ordinary-slide outline, page dimensions and editor revision.
   Read paths inherit ADR-0071's existing ungated read posture.
2. **Separate grant.** `slides-write` defaults to deny. It authorizes literal
   text replacement only. Existing grants confer nothing on Slides; the converse
   also holds. Object deletion needs its own operation and explicit consent.
3. **Typed scope.** The only request representation is `replaceAllText` and a
   batch contains exactly one request. No raw JSON, index arithmetic, object
   deletion, styling or force/rebase path exists. Matching defaults to
   case-sensitive; `--ignore-case` is explicit. An empty replacement removes
   matched text, as with Docs; this is distinct from deleting an object.
4. **Explicit pages.** Always send nonempty `pageObjectIds` naming ordinary
   slides, including when no `--slide` filter was supplied. Reject unknown,
   notes, layout and master IDs; deduplicate filters in deck order. Reject empty
   decks instead of sending an empty list, which the API interprets as unscoped.
   Speaker notes and templates remain readable or present in the snapshot but
   are not part of the write surface. This avoids relying on undocumented
   unscoped replacement reach.
5. **Order and two leases.** Validate, fetch Drive metadata, refuse MIME/shortcut
   mismatches, resolve `slides-write`, and only then read the presentation.
   Require a nonempty revision ID from that read, resolve page scope and compute
   the preview before returning a dry run. Before a real mutation run
   `gate_optional_leased_write`, then send one batch with mandatory
   `writeControl.requiredRevisionId`, and conclude the native lease audit.
   The API method is visible only within `crate::drive`. A rule's
   `require_lease: false` relaxes only the Drive lease requirement, never revision
   control; a volunteered Drive lease is still checked.
6. **Preview.** Count literal non-overlapping matches per shape/table cell,
   concatenating runs within each object. Never match across unrelated objects.
   Exclude notes/templates using the same ordinary-slide IDs as the mutation.
   Counts are estimates (Unicode case behavior may differ), never mutation
   guards: a zero estimate still sends the request. Server replies supply actual
   counts; proto3 omitted zero resolves to zero.
7. **Outcomes and logging.** Record `slides-replace`, result status, identities,
   revision and actual counts, never search/replacement text or server diagnostics
   that might echo prose. Dry runs do not log mutations or consume leases.
   A successful HTTP response with an unreadable body is reported as applied,
   with an inspection-before-retry message, and concludes the lease as allowed.
   Structured output preserves original prose; table output sanitizes controls.
8. **Revision diagnostics.** Google's
   [batchUpdate reference](https://developers.google.com/workspace/slides/api/reference/rest/v1/presentations/batchUpdate)
   specifies HTTP 400 on a mismatched revision. The narrow message marker
   `does not match the latest revision` produces a stale-revision outcome;
   other errors stay generic and preserve the server diagnostic for the caller.
   The exact marker has not been verified live for Slides. An unfamiliar marker
   remains a failure with no mutation; no automatic retry is introduced.
9. **Deferred.** Add-slide, deletion, shape insertion, styling and MCP. No live
   edits of user presentations are part of validation. Live drive.file-only
   behavior and exact stale-revision wording remain unverified.

## Consequences

- Operators can discover Slides object identities and replace text without
  widening existing grants or depending on numeric text offsets.
- Explicit page IDs make notes/template exclusion and preview scope reviewable.
- Revision control closes the read-to-write race; Drive leases retain the existing
  native backup, version checks and audit semantics.
- Full snapshots can be large. The bounded read may refuse a very large deck;
  selecting a slide filters output after fetching and does not reduce the payload.
- Preview counts are approximate, and notes/template editing requires future work.
- Slides native backups currently have no typed restore path. Operators need a
  configured `native_backup_folder_id` and can recover using the copied deck.
