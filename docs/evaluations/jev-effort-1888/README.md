# Effort routing evaluation — #1888

Status: live comparisons completed on 2026-09-23; results below. Provider
capability metadata is verified. Effort recommendations remain **uncalibrated**
for downstream task success; passing these checks does not establish that guarantee.

`inputs.json` freezes the 20 E1 problem-only issue inputs reconstructed on
2026-09-23 using the original `problem_only` section filters in the
[reproduction comment on #1779](https://github.com/rust-works/omni-dev/issues/1779).
The exact comment can also be found by its heading, “Validation: reproducing
the evidence against real issues”, in that issue. `labels.json` preserves
its hand-assigned class labels. `provenance.json` records construction and
the body-update caveat: #1486 was updated after the original cutoff, so the
historical comparison needs qualification. Comments and references are
excluded from this E1 dataset; use full-input and decision-comment cases
separately before claiming generalization to production routing.

Run from the worktree, using configured Jev credentials:

```bash
WT=/absolute/path/to/omni-dev/worktree
cargo run --manifest-path "$WT/Cargo.toml" --example jev_route_eval -- \
  "$WT/docs/evaluations/jev-effort-1888/inputs.json" \
  /private/tmp/jev-effort-results 2
```

The output directory must be new. This makes 400 Jev requests: 20 issues ×
5 ladder variants × 2 question variants × 2 repetitions. The ladder variants
are Anthropic, OpenAI, Gemini, all three together, and a versioned Anthropic
custom ladder. Each compares the original class-only questions with the
actual effort-aware questions generated by the route engine. Every request
uses the same frozen issue text. The harness records exact question maps,
inputs, resolved Jev model names, token usage, per-run elapsed time and
complete route results, including failures. It uses the production decoder,
so missing or unsupported effort answers cannot masquerade as valid advice.

Before accepting calibration, inspect:

- Class agreement with the original labels, per-stage shifts and no-design
  rates, comparing added-question effects against repeat-to-repeat noise.
- Single-ladder versus combined-ladder consistency for both class and effort.
- Unsupported/missing-answer failures (must be zero); no-work and insufficient
  outcomes; close calls; token and latency overhead.
- A separate fresh holdout of full-input issues, completed stages, difficult
  review and capability-limit cases, with effort expectations assigned before
  looking at outputs. The original dataset has class labels only, not
  independent effort labels or measured downstream task outcomes.

Do not describe hand-label agreement as probability calibration or proof of
lower downstream cost. Retain observed results and disagreements here, and rerun after criteria
changes using a fresh output
directory. #1885's model-class re-evaluation is related but does not replace
this evaluation of the added questions.

## Recorded run: 2026-09-23

Executed against **jev-1.13.0**: 400 original-dataset requests plus 120
holdout requests. `original-results.json.gz` and `holdout-results.json.gz`
are gzip-compressed JSON objects mapping output filenames to their complete
contents (question maps, frozen inputs and reports). `summary.json` records
the comparisons and run metrics. For example, inspect an archive with:

```bash
python3 -m gzip -d < original-results.json.gz > original-results.json
```

The fresh holdout contains public issue bodies #1870, #1880, #1861 and #1858,
plus two explicitly synthetic controls: a completed change and a mechanical
spelling correction. `holdout-expectations.json` was written before running
or inspecting holdout answers. Expectations are the implementer's judgement,
not an independent human evaluation or measurements of downstream models.
No question or criterion was tuned after inspecting these results.

### Observations

- **No effort decoding failures:** all 260 effort-aware requests succeeded,
  with every expected answer present and every effort choice/probability
  vocabulary valid. One of the 260 class-only requests timed out connecting
  to Jev (#1858, combined holdout, first repeat); its second repeat succeeded.
  The failed request is retained in the archive rather than removed from the
  record. Total: 519 successful requests, one transport failure.
- **Anthropic class agreement:** baseline 16/20 in both repeats; effort-aware
  17/20 and 16/20. Class changed in 1/40 paired comparisons, on #1691 from
  Opus to Sonnet (design confidence 0.24 → 0.14). The baseline had no
  repeat-to-repeat class changes; effort-aware had one. Implementation-class
  answers changed in 4/40 comparisons, without changing the overall class.
- **Other class shifts:** OpenAI changed in 4/40 paired comparisons, Gemini
  in 3/40, the combined request in 5/120 provider comparisons, and the
  versioned custom ladder in 1/40. Single-provider shifts all had design
  confidence below 0.4. They are not all below the heuristic 0.3 close-call
  threshold: Gemini #1687 moved Pro → Deep Think at 0.34 → 0.33, and OpenAI
  #1355 moved Astra → Sol at 0.36 → 0.23. More data is needed before adjusting
  that threshold or declaring a regression absent.
- **Batching differences:** comparing effort-aware single-ladder requests
  with their combined counterparts, classes differed in 2/40 Anthropic,
  5/40 OpenAI and 3/40 Gemini comparisons. Effort status/level differed in
  11/360, 4/360 and 4/360 model-stage comparisons respectively. Batching
  preserves namespaces and one-call behavior, but not identical judgements.
- **Effort repeat stability:** status/level changed in 5/180 Anthropic,
  4/180 OpenAI, 2/180 Gemini, 12/540 combined and 1/180 versioned comparisons.
- **Holdout behavior:** all 476 predeclared model-stage checks passed. These
  include no-design, bounded implementation, open research/design,
  permission-sensitive review, a fully completed issue and a mechanical
  change. Repetitions and ladder variants reuse the same six cases: this is
  not 476 independent examples. Fixed/unavailable profiles were excluded
  from checks requiring configurable levels, but included in no-work checks.

### Cost and limits

Over the two original-dataset repetitions (40 requests per variant),
Anthropic input tokens increased from 62,458 to 218,098 and output tokens
from 5,451 to 34,143. Wall time increased from 11.67s to 12.56s. Combined
ladders increased from 118,218 to 537,978 input tokens and from 15,554 to
94,456 output tokens; wall time increased from 12.81s to 16.00s. These are
observed run totals, not latency guarantees. One call per issue does not
mean unchanged token cost.

The results support the output contract and basic stage/model discrimination,
while showing that added questions and batching affect judgements. They do
**not** establish calibrated probabilities, a measured 90% downstream success
rate, or that the recommended level minimizes total cost. The original set
is problem-only and only Anthropic has inherited class labels. The fresh
holdout has four full bodies but no human comment threads, plus two synthetic
controls; it is small and its expectations were assigned by the implementer.
Forward task outcomes and independent labels remain necessary for stronger
claims. Keep the advice explicitly uncalibrated and retain the existing
model-class wording and close-call threshold until broader evidence exists.
