- **Changelog entries are fragment files, so pull requests no longer conflict on `CHANGELOG.md`** ([#2213](https://github.com/rust-works/omni-dev/issues/2213), [ADR-0097](docs/adrs/adr-0097.md)): a pull request adds `changelog.d/<issue>.<type>.md` (`changelog.d/vscode/` for the VS Code extension) instead of a bullet under `[Unreleased]`, and the release assembles them with `python3 scripts/changelog.py collect --component crate|vscode --version X.Y.Z`. Two pull requests in flight no longer touch the same hunk, and a branch forked before a release can no longer have its bullet applied inside the section the release closed (#2129). The `Changelog` check now validates every fragment (`check`), and on a pull request requires one (an extension one for a user-visible `editors/vscode/` change) and rejects a direct edit to either changelog (`check-pr`); `Changelog: none <reason>` and `Changelog: amend-released <reason>` trailers waive them as before. `scripts/check_changelog.py` is gone. Each changelog's existing `[Unreleased]` text is carried verbatim into its next release. See [changelog.d/README.md](changelog.d/README.md).
