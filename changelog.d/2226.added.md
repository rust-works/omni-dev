- **`omni-dev ai gateway`: an Anthropic Messages gateway in front of OpenAI-protocol models** ([#2226](https://github.com/rust-works/omni-dev/issues/2226), [ADR-0098](docs/adrs/adr-0098.md)): Claude Code, the Anthropic SDKs and anything that honours `ANTHROPIC_BASE_URL` can now use models served by OpenAI, Ollama, LM Studio, vLLM, OpenRouter or Fireworks AI. The gateway serves `/v1/messages` (streaming and not), `/v1/messages/count_tokens` and `/v1/models` on `127.0.0.1`, behind a token, Host and Origin guards.
  - Optional named upstreams route each request by exact/glob model rules (with aliases), then by bounded cached model discovery. Credentials remain upstream-specific; ambiguous ownership and catalog failures fail clearly without inference fanout or provider fallback.
  - Native Bedrock Claude supports bearer-authenticated InvokeModel and binary InvokeModelWithResponseStream, preserving tools, thinking and provider signatures. Catalog paths are configurable; no SigV4 credential chain is added.
  - It translates to Chat Completions or the Responses API, or passes through to an Anthropic-compatible upstream such as Fireworks' own Anthropic surface.
  - It translates tools, `tool_choice`, thinking and effort, structured output, images, stop reasons and usage, and re-frames streams as Anthropic's full event sequence.
  - The gateway signs the thinking blocks it returns and replays its own on the next turn.
  - Every request field is classed as translated, ignored (reported in an `x-omni-dev-gateway-ignored` header) or rejected, in one table that `ai gateway fields` prints; unknown fields are rejected unless `OMNI_DEV_GATEWAY_UNKNOWN_FIELDS=warn`.
  - `ai gateway serve` runs it in the foreground, `ai gateway env` prints the client settings, and the daemon hosts it as the `anthropic-gateway` service.
  - A weekly job compares the field table with the Anthropic SDK's types.
  - See [docs/anthropic-gateway.md](docs/anthropic-gateway.md).
