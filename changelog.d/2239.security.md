- **TLS, certificate-store, zlib, MCP and Tokio dependencies updated to clear 11 RustSec vulnerabilities and one unsoundness advisory** ([#2239](https://github.com/rust-works/omni-dev/issues/2239)): `rustls` 0.23.46 (RUSTSEC-2026-0346 to -0349: `Debug` output exposing TLS secrets, data sent to the outer server after ECH rejection, pre-authentication Brotli certificate decompression of up to 1 GiB, and a ServerHello key-exchange downgrade), `rustls-webpki` 0.103.16 (RUSTSEC-2026-0382, distrusted intermediates accepted), `webpki-roots` and `webpki-root-certs` 1.0.11 (RUSTSEC-2026-0381 and -0383, distrusted emSign intermediates), `libz-sys` 1.1.32 (RUSTSEC-2026-0418, build script leaking environment variables) and `rmcp` 3.9.0 (RUSTSEC-2026-0457, -0461 and -0462, in its OAuth client and Streamable HTTP transports, which the stdio MCP server does not use). `tokio` 1.54.1 clears RUSTSEC-2026-0386 (`AsyncFd::new` I/O safety), which `cargo deny` reports as an error because `tokio` is a direct dependency; `chacha20` and `clipboard-win` move off yanked releases. The TLS and certificate fixes apply to every outbound HTTPS request. All are lockfile-only bumps.
